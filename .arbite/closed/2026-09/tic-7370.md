## Description
Agent feedback (diku tic-6949): 'vcall symbol all_wizards_from_env' showed local.run and a test as callers but missed serve.py, which calls it at module level inside if __name__ == '__main__' -- no enclosing symbol. 'A real gap for entry-point scripts.'

Cause: GraphBuilder drops CALLS edges whose caller is a module unless module_call_edges=True (graph.py ~L270), AnalysisOptions.module_calls defaults False (store.py), and query.CallGraph only keeps function/method/class endpoints, so even with the option on, module callers vanish.

Change:
- Stores default module_calls=True (AnalysisOptions default for init; existing stores pick it up only if config.json lacks the key -- decide and document; simplest is: treat missing key as True for stores, keep analyze's default False so the web viewer's call-flow mode is unchanged).
- query.py: keep CallGraph semantics (modules are not call-flow nodes, so cones/entries/reach are unchanged), but index module->callee CALLS edges separately and surface them: symbol gets 'module_callers' ("path:line" strings, the call sites), impact includes them in direct_callers as "<module id> path:line (module)" and their files in files/test_files.
- A function called only from module level must no longer be classified 'orphan' / counted possibly-unused; role 'entry' logic should treat a module caller as a caller (role internal, or a distinct 'module-called' -- pick one, document in AGENTS.md).

Acceptance: tests with a fixture file doing if __name__ == '__main__': main(); symbol main lists the module call site; impact main lists the file; orphans no longer lists it. AGENTS.md 'Reading the output' mentions module_callers.
