## Description
User request: "Import graph should implement a very similar feature to the call flow
trace depth feature."

Call flow's focused ("rooted") view carries a `Trace depth` knob (`rootDepth`, tic-7a5e,
callFlow.ts) that controls how many hops it walks from its root in each direction. The
import graph's Local View (tic-d7d7) is the analogous focused state, but its reach is
hard-coded to exactly one hop in both directions from the centre file -- there is no depth
control at all.

Scope, confirmed with the user 2026-09-02: add a "Trace depth" number control to the import
graph's Local View so a focused view walks N import hops from the centre file -- its imports
below and its importers above -- instead of the current fixed single hop. Default 1,
preserving today's behaviour. Like call flow's `rootDepth`, it is a focused-state knob and
has no effect on the whole-graph (unfocused) view.

WORK
1. `web/src/modes/importGraph.ts`: extend `ImportGraphParams` with a numeric `localDepth`
   (default 1). Generalise `neighbourhoodOf` to walk `depth` hops in both directions from
   the centre -- forward `fileImports` edges for what the centre imports, the reverse
   (`fileImporters`) for who imports it -- still dropping any neighbour the current
   exclude/file-query scope has removed from the tree (the tic-56b2 unresolved-shape
   guard). Keep the node/edge rule unchanged: the node set is the depth-N neighbourhood,
   and every import edge with both ends in the set is drawn (so a dependency two neighbours
   share stays visible).
2. Thread the param through `select()` (`visibleFiles = neighbourhoodOf(..., depth)`) and
   reflect it on the scene so a focused view that changes no node id and no size (the
   tic-531b cache trap) still re-lays-out; the params are already serialised whole into
   `cacheKeyOf`, so a depth change re-derives the layout for free -- make sure nothing about
   the Local View spacing/layout keys off the old hard-coded assumption.
3. Wire the control: `defaultParams` gains `localDepth: 1` and the mode declares a
   `paramNumbers` entry labelled "Trace depth" (min 0, max 4, step 1, mirroring call flow's
   `rootDepth`), with a reader-facing `ParamHelp` sentence. `registry.test.ts` requires an
   explanation on every control of every registered mode.
4. Docs: update the `ImportGraphParams`/`neighbourhoodOf`/Local View docstrings and the
   module header claim that Local View is "one hop ... not two hops" -- the hop count is now
   a knob defaulting to one.

Acceptance criteria
- A focused (Local View) scene at the default depth is unchanged from before this ticket.
- depth 0 draws only the centre file (no neighbours, no edges); depth 2 draws files two
  import hops out in either direction plus every import edge between drawn files.
- The "Trace depth" control renders in the params panel, only affects the focused view, and
  re-derives the layout when changed (the elk cache does not serve a stale layout).
- Tests cover: `neighbourhoodOf` at depth 0/1/2 in both directions, an isolated file at any
  depth, the visible-scope drop, `select()` node/edge sets per depth, and the param
  metadata/help.

Verification: cd web && npm run test && npm run build. npm run dev: open a Local View at
depth 1, raise Trace depth to 2 and confirm the neighbourhood widens to two hops and the
layout re-runs.
