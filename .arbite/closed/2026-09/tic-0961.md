## Description
Follow-up to tic-1250 (nearest-line hover highlight + double-click-to-fly). Two additions: (1) holding Shift and double-clicking the nearest relationship line on empty canvas flies the camera to the line's SOURCE (its from endpoint) instead of its destination, reusing the same goto flight; an edge without a resolvable from no-ops. (2) The near-pointer popup currently prefixes the nearest (bold) line with '>' (a CSS ::before, added by hand in styles.css) to show the plain double-click direction; while Shift is held that prefix should become '<' so the pointer signals which way the next double-click will take the view. Shift is the marquee modifier on empty canvas, so a shift press currently starts a marquee gesture and the empty-canvas double-click detection (which lives in the pan branch of useViewport end()) never fires for it; the shift+click path must be routed into the same double-click detection, deferring the marquee overlay until it actually drags so a mere shift+press does not clear the nearest highlight and its source target. Acceptance: plain double-click still flies to 'to'; shift+double-click flies to 'from'; the popup arrow reads '>' normally and '<' while shift is held; marquee/drag behaviour and the nearest-line clearing gates are unchanged; 962+ tests pass, tsc and vite build clean.
