## Description
Small, self-contained, and it unlocks the type-flow overlay later.

A callable's return annotation exists today only inside the `signature` string, so any consumer wanting it has to parse Python out of text. Add a `returns: str | None` field to SymbolDef (adventure_call/models.py), populate it in _PythonExtractor._signature / _build_symbol (adventure_call/parser.py) from the `return_type` field of the function_definition node, include it in to_dict, bump SCHEMA_VERSION, and mirror it in web/src/data/types.ts (hand-written from models.py, must stay in sync).

Store the annotation as written -- do not normalise, resolve or evaluate it. `list[ToolResult]`, `"Session"` (a string forward reference) and `None` are all legitimate and the consumer decides what to make of them.

Current coverage for context, measured on the ../carnot export: 1094 of 2528 callables carry a return annotation, and 1270 of 3539 params are annotated. Partial, but honestly partial.

Verification: parser tests for an annotated function, an unannotated one (None, not empty string), an async function, a method, a string forward reference, and a complex generic. Confirm the signature string is unchanged for every existing fixture -- this ticket adds a field, it does not reshape signatures. Run the Python test suite.

## Notes
- 2026-09-01T11:24:49 claude.opus.001: Implemented and verified end to end against ../carnot.

`SymbolDef.returns: str | None` in models.py, populated by a new `_PythonExtractor._returns` reading the function_definition's `return_type` field, included in to_dict, SCHEMA_VERSION 1 -> 2, mirrored in web/src/data/types.ts.

Stored as written, as specified: no normalisation, no resolution, no evaluation. `list[str]` stays `list[str]`, `"Session"` keeps its quotes, and `None` the type is the four-character string while a function with no annotation gets Python `None` -- a distinction the docstrings on both sides spell out, because a consumer that conflates them is wrong about 276 functions in carnot alone. The one liberty taken is whitespace: a wrapped annotation is flattened to one line exactly as `_signature` already flattens wrapped parameters, so `-> tuple[\n int,\n str,\n]` reads back as `tuple[ int, str, ]`. That is a formatting concern, not a semantic one, and it is documented.

Classes get None rather than an empty string; verified 0 classes carry a non-null value in the real export.

THE FIELD IS NOT JUST CONVENIENCE -- IT IS MORE CORRECT. Measured on ../carnot: 1071 of 2445 callables (43.8%) carry a return annotation. Cross-checking against the old way of getting this -- looking for '->' in the signature text -- the two agree on 2444 of 2445, and the single disagreement is the new field being right: my_plugins/tools/test_camoufox_browser.py:22 is `def do_GET(self):` followed by the comment `# screenshot endpoint -> a 1x1 PNG`. Signature-text matching sees the arrow inside the comment and reports a return annotation that does not exist; `return_type` correctly reports None. Small, but it is exactly the class of bug that motivated the ticket, and it means tic-59b1's type-flow overlay would have started from at least one fabricated edge.

Distribution for context: None 276, str 155, bool 69, CommandResult 49, int 45, dict[str, Any] 29, ToolResult 23. Plenty of real generics (`tuple[LLMResponse, int, Usage]`, `tuple[list[Any], int, int] | None`), which is the material tic-59b1 will normalise.

TWO DECISIONS WORTH RECORDING:

- The TypeScript mirror is `returns?: string | null`, OPTIONAL rather than required. The app reads whatever `out/` currently holds, and a schema_version 1 export predates the field entirely, so a required field would be a claim about data that may not be there. Same reasoning as `root_abs` (tic-7f0b), which is optional for exactly this reason. Making it required also broke five test fixtures, but that is not why -- honesty about old exports is.
- Two writer tests asserted `schema_version == 1` as a literal, one of them with the message "new kinds are additive; the schema is unchanged" (tic-82b0). That claim is still true; the version has simply moved for an unrelated reason. Both now assert against the imported SCHEMA_VERSION constant, so the next real schema change does not have to hunt down copies of a number, and tic-82b0's comment is preserved explaining why it is written the way it is.

Tests: 11 new (120 -> 131). Annotated function, unannotated (None, not ""), `-> None` kept as its text, async, string forward reference keeping its quotes, wrapped annotation flattened, method, decorated method, class, the field appearing in to_dict, and -- per the ticket -- an explicit assertion that no signature string changed shape.
