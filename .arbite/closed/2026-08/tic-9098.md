## Description
Make the Filter Files box a real query, and let it drive what the canvas shows.

QUERY SYNTAX (parse in a pure, unit-tested module, e.g. src/data/query.ts)
- Plain text: today's case-insensitive substring match on the path.
- 'r:<expr>': treat the rest as a regular expression (case-insensitive). An invalid expression must show as an inline error on the input, never throw.
- '>' prefix: widen the match from the path to ALL properties of the file and its symbols -- symbol names, signatures, docstrings, decorators, bases, module docstring.
- '>' always comes first, so exactly three prefix forms are legal: '>', 'r:', '>r:'. Anything else is literal text.
Keep matchTree() in src/ui/FileTree.tsx as the tree-pruning step and feed it a predicate built by the parser, rather than growing the matching logic inside the component.

VISIBILITY TOGGLE
A small square eye button immediately to the right of the search input. When active, the workspace scene is re-derived from what the filter leaves visible -- files that do not match are absent from the canvas, not just from the sidebar tree. When inactive (default) the filter only prunes the sidebar tree and the canvas is unaffected.
Route this through the mode's select phase the way the exclude list already is (src/data/filters.ts -> deriveWorkspace in src/data/derive.ts -> src/modes/fsTree.ts) so the canvas never learns about search directly. Persist the toggle with the rest of the mode state.

Note '>' searches symbol properties, so an all-properties query can match a file through a symbol deep inside it; that file must still appear as a file in the tree and on the canvas.

EXIT: each of the four query forms matches as described; an invalid regex reports inline; the eye toggle makes the canvas track the filter and survives a reload.
