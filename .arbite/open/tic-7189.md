## Description
High value for very little work, and available early -- it needs only the call graph and the external call targets already in the export, not the reads/writes work.

Seed a small list of effectful external targets (open, pathlib writes, subprocess, socket, requests/httpx, os.environ, print, logging, random, time, datetime.now) each tagged with an effect kind -- filesystem, network, process, env, console, nondeterminism. Then propagate upward through tic-a8a6's condensed DAG: a function's effect set is its own direct effects unioned with those of everything it calls. Reverse topological order over the DAG makes this one memoised pass; a cyclic component's members all share the component's effect set, as with reach in tic-1ecc.

The result -- "this function transitively touches the filesystem and the network" -- is one of the strongest possible inputs to the eventual LLM summarisation layer, and it is immediately useful to a human deciding whether something is safe to call, cache or reorder.

The inverse is just as interesting: a function with an EMPTY effect set, no writes and no nondeterminism is probably pure. Probably, and the UI must say probably -- 902 computed callees in ../carnot mean an unseen dynamic call could do anything. A purity claim that is wrong once is worse than no purity claim.

Make the seed list data and user-extensible, for the same reason tic-22db's decorator map is: every codebase has its own I/O wrappers, and half the value comes from someone adding `db.execute` to the list.

Verification: unit tests for direct effects, one-hop and multi-hop propagation, propagation through a cyclic component, and a genuinely pure leaf. Against ../carnot, report how many functions come out pure and spot-check five by eye. npm run test, tsc -b.
