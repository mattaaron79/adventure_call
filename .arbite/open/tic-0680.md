## Description
Groundwork shared by tic-ea9d (import-graph node expansion) and tic-2caf (inspector Imported By). Two parts, both pure and unit-testable.

PART 1 -- reverse index. web/src/data/derive.ts currently derives file->file import edges forward only (deriveFileImports, ~lines 191-231, returning FileImportEdge[] of {source,target,count,symbolIds}). Add a memoised reverse index beside it, e.g. deriveFileImporters(fileImports): ReadonlyMap<string, FileImportEdge[]> keyed by edge.target (the imported file) -> the edges that import it. Use the same WeakMap-per-input-array memoisation pattern every other derivation in that file uses (see fileImportCache / sccCache). Expose it on the Workspace interface as fileImporters, populated in deriveWorkspace next to fileImports/importCycles. deriveFileImports already drops self-imports and unresolved targets, so no extra filtering is needed.

PART 2 -- extract the row builder. web/src/modes/fsTree.ts owns the expanded-file container vocabulary: the Row interface, rowId/sectionRow/memberRow helpers, fileRows(workspace, file) and layoutContainer(rows) plus PlacedRow/ContainerLayout and the CONTAINER/CHAR_W constants those need. tic-ea9d needs all of it for the import-graph mode, and importing one mode from another is wrong -- the registry is the only cross-mode seam. Move that vocabulary into a new web/src/modes/fileDetail.ts and have fsTree.ts import it. fs-tree behaviour must not change: its row output, container sizing and the fsTree.test.ts expectations are the guard (update import paths in the tests, not expectations).

PART 3 -- the new section. Give fileRows an options bag with importedBy: boolean, defaulting to false so fs-tree is untouched. When true, emit an "Imported By" section ABOVE the existing "Imports" section (the user asked for that order explicitly), built from PART 1s reverse index: one row per importing file, not per symbol -- id like rowId(path, "impby:" + importerPath), symbolId null (it names a file, not a symbol), kind "module", label shaped like the Imports rows so the two sections read as siblings, and gotoTo set to the importer file path so the canvas renders its camera-goto button generically. Keep the section omitted when the file has no importers, matching how the other sections behave.

Verification: cd web && npm run test (add tests for the reverse index -- fan-in, memoisation on the same array identity, empty for a file nobody imports -- and for fileRows with and without importedBy, asserting Imported By precedes Imports); npm run build for the typecheck. No visual change should be observable in Files and symbols mode -- that is the point.
