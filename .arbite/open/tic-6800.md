## Description
Agent feedback (diku tic-0105): a comma-separated 'vcall find' query returned nothing and the agent fell back to targeted reads. --kind already takes comma-separated values, so agents reasonably expect the pattern to.

Change: in Workspace.find (non-regex mode), split PATTERN on commas, strip, and match any part; rank per part as today and interleave/dedupe. Leave --regex untouched (commas are literal there). The NotFound payload should echo the parsed parts so a miss is self-explanatory. Also note in help that find matches definitions only (tic-6949 there expected call sites) and point to 'impact'/'refs' for usages.
Acceptance: tests for 'find login_user,make_user' returning both; help text updated.
