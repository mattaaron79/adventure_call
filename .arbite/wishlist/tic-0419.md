## Description
NOT FOR THE ORCHESTRATOR -- filed to wishlist/ for discussion first.

Today the tidy tree grows left to right: depth is the x axis, siblings stack down y (src/layout/tidyTree.ts). The user wants an option to grow DOWNWARD instead -- depth on y, siblings spread along x -- the familiar org-chart reading of a folder hierarchy.

SHAPE OF THE WORK
- tidyTree.ts is already pure and orientation-agnostic in principle: the algorithm is 'tier offset on one axis, stacked block on the other'. Parameterise the axes rather than writing a second layout.
- Elbow connector routing has to follow the orientation; the corner turns the other way.
- Directory group rects and the expanded file containers keep their own internal top-to-bottom row layout regardless -- only the TREE orientation flips, not the contents of a container.
- Expose it as a mode param (src/modes/fsTree.ts defaultParams) so it is switchable at runtime and rides along in saved presets automatically (tic-83ec already carries params into presets).

OPEN QUESTION
Vertical trees get very wide very fast -- 191 files with a downward layout is a long horizontal band, where the current rightward layout produces a tall narrow one. Worth deciding whether vertical should also cap sibling spread (wrapping a wide row of leaves into a block) or whether the honest wide band is what is wanted. Do not guess -- ask.
